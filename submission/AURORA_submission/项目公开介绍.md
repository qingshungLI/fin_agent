## 项目名称

**AURORA Alpha Harness：可审计的自演化量化研究智能体**

品牌简称：AURORA。中文展示名：极光量化研究。核心表达：**让每一次因子探索，都留下可追溯的证据。**

## 项目摘要（200 字以内）

AURORA 是面向量化投研的可审计、自演化研究智能体。系统以经济机制组织假设空间，由大模型协同完成提案、表达式构造与逻辑审查，经实验冻结、统计检验和证据核对，利用训练段异质性提出下一轮假设。研究过程通过二维／三维地图、父子谱系和证据报告呈现，并支持检查点恢复与自有数据接入。项目已产出真实研究记录，当前归档尚无独立确认因子，旨在为研究团队提供可复核、可积累的投研工作流。

## 项目公开介绍

### 解决什么问题

量化研究需要不断提出、检验和修正假设。在这一过程中，候选表达式、数据版本、检验结果和修改理由容易分散在脚本与笔记里。研究人员既要判断信号是否存在，也要解释它在什么条件下成立、为何失效，以及后续应研究什么。

AURORA 将这些环节组织为可执行的研究流程。研究对象同时包含经济机制、表达式、预测周期和必要断言；每一次探索都形成可追溯的记录，供研究人员复核与后续实验使用。

### 系统如何工作

1. **组织研究空间。** 以 10 类机制与 7 种表达形式建立 70 个初始研究坐标，明确探索位置。这是研究目录，后续还可以产生子代假设。
2. **协同提出假设。** 完整引擎中的大模型承担提案、操作化、审查、盲下注、结果核对与归纳六类角色，按角色接收限定字段。
3. **冻结实验合同。** 在测量前记录假设、表达式、配置与代码指纹，为恢复运行及结果追溯提供依据。
4. **检验并记录证据。** 结合统计测量、必要断言与安慰剂检验，保留通过、未通过和证据不足的区别；独立确认另设准入流程。
5. **提出下一轮研究。** 从训练段条件、方向及父子关系中生成后续假设，保存演化谱系。训练选择得到的条件仍需重新检验。
6. **交付研究产物。** 通过控制台查看批次、机制地图、结构证据与日志，并导出报告；自有数据 SDK 提供独立实验入口。

### 核心创新点

| 创新点 | 具体实现 | 对研究人员的价值 |
| --- | --- | --- |
| 机制约束的假设生成 | 机制地图、受限表达式、必要断言与逻辑审查 | 可以追问每个候选的经济含义和可检验条件 |
| 证据驱动的假设演化 | 训练段异质性、方向诊断、条件／交互子代和父子比较 | 为下一轮探索提供明确依据与可复核谱系 |
| 研究过程可审计 | 角色字段白名单、实验冻结、检查点与审计记录 | 可以追溯结论来自什么数据、配置和研究步骤 |
| 研究成果可积累 | 规律记录、分阶段贝叶斯研究记忆与后续探索调度 | 将失败原因和条件线索保留为研究资产 |
| 可交互的研究交付 | 二维／三维机制地图、证据详情、自有数据实验入口 | 支持演示、审查和在自有数据上的试用 |

这些创新描述的是项目的组合设计与实现，不主张未经验证的行业首创。

### 已实现与已观察到的成果

项目已包含 Python 研究引擎、React 控制台、自有数据 SDK、组合相关模块和回测适配代码。主流程支持研究预算、暂停／停止、检查点恢复及受一致性约束的续跑。源码入口与部署要求见 [交付导航](docs/DELIVERY.md)。

[2026-09-09 归档快照](docs/research/2026-09-09-progress.md)记录了 20 次尝试、15 个完成候选，其中 9 个 UNDECIDABLE、6 个 FAIL，6 个子代已完成评估与比较，独立确认数为 0。这组结果支持展示真实研究流程和可审查产物；快照不随后台运行自动更新。

归档中 C011 在训练段出现反向线索，但后续探索段方向没有保持。这一案例展示了系统如何保留证据冲突，帮助研究者决定后续是否继续投入。该归档尚无自动发现的可用训练条件规则，不能将条件演化的代码能力表述为本轮已取得的验证成果。

`report/` 中另有 Core Lab 案例截图，可用于辅助说明条件筛选和规律记录。截图与上述归档属于不同证据来源，应分别展示；截图中的 promote 表示继续研究的筛选动作，无法替代正式确认。

### 产品价值与落地路径

优先面向有自有数据和研究流程的小型量化团队、金融工程实验室及投研工具开发者。产品切入点是研究流程管理、批次复核和假设迭代。

拟议落地分为三步：先以本地工作台接入团队已有数据，完成一条可复核的因子研究流程；再通过 SDK 嵌入既有研究工具；最后在试点需求明确后完善团队协作、权限及运维能力。

拟议商业模式为本地部署与技术服务、团队使用许可及数据适配服务。目前材料未提供客户签约、收入或节省成本的量化证据，因此将这些内容作为商业验证计划。试点可测量研究合同完整率、人工复核时间、异常恢复成功率及每个完成候选的计算与模型成本。

## 技术与证据口径

- 完整引擎的六类 LLM 角色共用模型，不应描述为六个独立模型投票。
- 自有数据 SDK 的独立实验路径不调用外部模型，演示时需要说明实际入口。
- 70 个坐标表示初始探索空间；尝试数、完成候选数、子代数和正式确认数分别统计。
- `engine/evidence.py` 中的 e 轨迹为实验性诊断，正式判定不消费它；当前 B/H 确认代码采用冻结批次 Holm 校正及必要断言判定。
- A 段 fast 结果、训练段条件筛选和正 IC 均不能作为独立确认或交易收益证明。
- 冻结指纹和审计记录支持一致性检查与追溯，不表述为不可篡改或完整安全认证。
- 当前交付为源码仓库，依赖、授权数据及模型凭据需配置；机构级权限、运维与商业可用性仍需试点验证。
